# M01-T03 – Mượt phía client

## Kế hoạch
1. Xây dựng module `client/js/09-predict.js`:
   - Client prediction (Dự đoán phía client): Khi người chơi bấm phím di chuyển, vị trí nhân vật được tính toán và áp dụng ngay lập tức trên máy khách mà không cần chờ snapshot từ server.
   - Lưu trữ `pendingInputs = [{ seq, mx, my, dt }]`.
   - Server reconciliation (Sửa sai theo máy chủ): Khi nhận snapshot `snap.me` từ server kèm `ack`:
     - Đồng bộ lại vị trí theo snapshot của server (`snap.me.x, snap.me.y`).
     - Lọc bỏ các input cũ có `seq <= snap.ack`.
     - Chạy lại (replay) các input còn lại từ vị trí server xác nhận.
   - Entity interpolation (Nội suy các thực thể khác):
     - Lưu trữ buffer vị trí các entity khác theo thời gian (`snapBuffer`).
     - Render các entity khác lùi lại một khoảng `CONST.INTERP_MS = 100ms`.
     - Nội suy tuyến tính (lerp) tọa độ `(x, y)` và góc ngắm `aim` giữa 2 snapshot gần nhất, giúp chuyển động hoàn toàn mượt mà, không giật cục.
2. Xây dựng bảng Debug F3 trong `client/js/06-render-hud.js`:
   - Lắng nghe phím F3 để bật/tắt bảng thông số debug.
   - Hiển thị trên `uiCanvas`:
     - FPS (tính toán từ requestAnimationFrame).
     - Ping (ms, đo bằng ping/pong định kỳ).
     - Server Tick hiện tại.
     - Số lượng entity trên màn hình.
     - Tọa độ người chơi `(x, y)`.
3. Đo ping định kỳ trong `client/js/01-net.js`:
   - Gửi `{ t: 'ping', c: Date.now() }` mỗi 1 giây.
   - Nhận `{ t: 'pong', c, s }` tính `ping = Date.now() - pong.c`.
4. Viết unit test `server/tests/predict.test.js`:
   - Kiểm tra logic reconciliation: khi vị trí server lệch, replay lại các pending input cho ra vị trí chính xác.
   - Kiểm tra logic lerp nội suy 2 mốc thời gian.
5. Kiểm tra tự động 2 tab qua Chrome DevTools Protocol:
   - Di chuyển cả 2 tab, kiểm tra ping và tọa độ cập nhật liên tục, không bị kéo giật ngược vị trí (rubber-banding).
6. Chạy `tools/run_all.py` kiểm tra toàn bộ.
7. Hoàn thiện report, cập nhật `docs/TIEN-DO.md`, commit & push.
